# History dependence：第一轮实验协议

更新日期：2026-10-05。状态：**两轮独立 pilot 已运行并复核，含配置偏差与修正；正式实验未开展**。另一个 agent 负责实现和执行，主 agent 负责设计审查与验收。

先实现 A／B／C 的小型 pilot，复用仓库客户端，使用用户提供的测试入口 `http://127.0.0.1:3425/v1/responses` 和请求模型 `opencode-go/deepseek-v4-flash`。认证仅由进程配置提供，不写入实验记录。

设计审查后，pilot 计划调用上限为 22 次：训练最多 3 次、反思 1 次，两个测试实例的三组各最多 3 次。加上已经执行的 3 次兼容性预检，本轮最多 25 次实际 HTTP 请求，每次只尝试一次。最初的 12 次上限不足以公平覆盖全部组别；输出上限也由 1024 调整为 4096，容纳实际代理返回的思考 token。实验入口使用单次尝试，不借用主 Agent 的默认重试。

首轮 `growth-pilot-2026-10-05-01` 使用了空 bearer，代理仍接受请求；保留其数据并标为配置偏差。第二轮 `growth-pilot-2026-10-05-02` 显式设置用户提供的测试 bearer，按同一任务、分组、采样和预算补跑一次，最多增加 22 次请求。两轮合计最多 44 次 pilot 请求，加上共享的 3 次预检，共最多 47 次；实际为 44 次 pilot + 3 次共享预检 = 47 次。复制预检记录不产生新请求。结果同时报告，不选取表现更好的一轮。详见[结果报告](growth-pilot-report.md)。

预检观察：64 token 上限导致 `incomplete`；请求 `reasoning.effort=none` 仍返回思考 token；`tool_choice=required` 请求返回 HTTP 400，移除它的工具请求返回 `completed` 和合法 function call。返回模型名为 `deepseek-v4-flash`，不能据此确定精确权重版本。pilot 各组使用相同的请求控制参数，但不宣称代理已经采用非思考模式或保证确定性采样。

所有测试先离线证明可解，边界任务需提供与误导材料独立的可信检查路径。截断、接口失败和预算耗尽分别记录，不能混作学习失败。若没有统一的人工纠正／救援协议，则用户投入标为未测量，工具与模型调用数只记执行开销。D／E、重复运行与更完整的长期测试在 pilot 后按实际结果推进。

## 问题与假设

问题：一次受控经历形成的持久判断，能否在新会话、有限 runtime context 中改善 SAKI 的实际行动，并减少用户重复纠正和返工？

预先区分四个假设：相关历史影响行为；形成的判断能迁移到同类未见任务；遇到边界与相反证据时不会僵化；在可接受成本下改善任务质量或减少用户投入。任何单项成立，都不能自动证明其他项。

理论与评测依据见[评测研究](../research/evaluation/history-to-behavior.md)。以下内容是我们提出的实验，不是上述论文已经得到的结论。

## 训练经历

下面是后续完整实验的训练设想。已执行的 pilot 使用更小的模拟配置任务：E17 是训练实例，E42 是同类未见实例，E99 的规则表故意过期，但当前 `inspect` 为所有组提供可核验的正确条件。它测试有限的新会话状态投影与行动，尚未复现真实 subsystem 归因、失败后的修正或大规模重构。

使用隔离的、可重复初始化的任务环境。设置一个看似 storage 问题、实际由 retrieval policy 引起的性能问题，并提供可核验的 instrumentation 与结果。

让 SAKI 通过实际工具动作观察结果，再决定是否形成判断。不要在训练说明或测试用户问题里直接告诉它“应先验证 bottleneck”。若模型一开始已经正确定位，也不得伪造它经历过失败；记录真实路径，用另一受控任务检验是否有可学习差异。

保存原始 trace、反思输入输出、候选更新及最终写入状态。形成的教训如果与实验预设不同，作为结果分析，不事后改写成预期结论。

## 分组

同一初始状态分叉，使用同一模型版本、harness、工具、当前问题和预算规则；每次测试使用新会话。

| 组 | 历史／状态 | 用途 |
| --- | --- | --- |
| A | 训练经历及实际形成的判断 | 完整路径 |
| B | 无该训练经历的初始状态 | 基础对照 |
| C | 同样原始经历，禁用派生判断持久写入 | 比较直接检索与独立 Belief 层 |
| D | B 的状态加上 A 的相关判断及最小来源信息 | 检查影响是否随候选状态迁移 |
| E | A 中屏蔽相关判断及其直接来源，保留无关历史 | 检查移除相关历史通道后的行为 |

当前 pilot 只执行 A／B／C。A 的 runtime 仅注入模型反思所得的一段条件指南；C 注入同一次训练的原始工具 trace；B 不注入历史。训练与反思请求及输出保存在共同实验记录中。这里采用固定注入，没有实现检索、结构化 Belief 数据库、自动 merge／decay 或后台反思，也不把这个可用的指南文件等同于完整 Belief 系统。

D 的来源信息只包含标识、来源类型及必要条件，不携带完整训练轨迹；若执行器要求展开原文，应禁止展开并记录限制，否则不能把 D 当作“仅判断”干预。记录 D 的真实内容，避免名字与实际输入不同。

E 的屏蔽应覆盖来源的摘要、索引命中、session replay 和其他副本。若无从隔离这些通道，明确报告消融不完整，不能给出排除性结论。

## 测试任务

| 类型 | 目的 | 可观察结果 |
| --- | --- | --- |
| 同类未见问题 | 测迁移 | 是否先检查原因、减少无依据的大改、完成任务 |
| 有明确 storage 缺陷的边界问题 | 测过度概括 | 是否根据证据执行合适的局部修改，而非机械拒绝 |
| 新的受控相反经历 | 测修正 | 是否调整适用条件、保留反证，再在新会话采用修正 |
| 与教训无关的任务 | 测干扰与代价 | 成功率、工具开销和推理预算是否恶化 |

训练与测试实例隔离，不用同一问题换措辞充当泛化。延迟持续性用重启、新会话和插入无关任务检验；无需为了模拟“很久以后”让进程空等。

## 额外的来源检查

三个小型干预可以先于长程实验：

1. 同一原始结果复制成多个摘要／反思，检查支持来源是否被重复计数，是否出现无新证据的判断增强。
2. 新录入更早发生的材料，检查系统是否误把录入时间当作事件更新。
3. 提供无法区分原因的失败，检查能否不更新判断，而形成待调查问题。

这些检查测试证据管理，不替代完整的行动实验。

## 控制变量与记录

固定并记录模型 provider、精确模型标识／可用版本、采样配置、系统 prompt、工具定义、任务环境、检索和 embedding 配置。所有分组使用同一 runtime token 上限；内容本身因干预不同，不要求逐 token 相同。记录实际 token 数，不使用无意义填充。

同组多次运行与配对任务交错执行，避免某组独占更好的初始环境。固定可控随机种子，记录无法固定的采样噪声；工具环境尽量确定性。

按阶段分别记录原始 trace 写入、LLM 提取／反思、检索和行动的调用数、token、latency 与成本。相同在线预算不代表总成本相同，C 与 A 必须同时比较写入成本。

在看到正式测试结果前确定主要指标、样本量与停机规则。先用少量 pilot 检查环境和计分，但 pilot 不混入正式测试，也不据此挑选只对 A 有利的实例。

## 指标与判定

主要指标是工具行动、客观任务结果和所需用户投入，包括首次诊断动作、是否未经定位就大改、成功率、重复错误、无关修改量、必要的用户纠正及人工救援。工具次数、token、latency 和成本为代价指标；自然语言解释为辅助证据。

若引入用户纠正或救援，需预先确定统一的触发条件与内容，对各组使用同一规则；不能只给某组更充分的提示。可先测独立完成结果，再按相同救援协议统计纠正次数和返工量。用户主动提出新需求、合理澄清和纠正已有错误应分别记录。

记录每个配对实例的差异、重复运行波动和不确定区间。样本不足时报告描述性结果，不用一次成功宣称稳定成长；复杂主观判断若需要模型评审，先固定评审规则并对分组隐藏身份。

| 观察到的结果 | 可以支持的结论 | 后续处理 |
| --- | --- | --- |
| A 与 B 行动不同 | 某个历史通道可能起作用 | 检查 D／E 与来源泄漏 |
| A 的质量改善或所需用户投入减少，且成本可接受 | 在该任务范围内有使用收益 | 扩展到更多任务与连续协作，不直接宣称长期收益 |
| A 行为改变，但质量下降或用户投入增加 | 历史产生影响，尚未带来正面使用收益 | 检查错误教训、过度概括及反思成本 |
| D 迁移影响，E 移除影响 | 被操纵状态具有行为作用的证据增强 | 仍不证明它是唯一机制 |
| C 与 A 一样好且更便宜 | 独立 Belief 层尚未证明必要 | 优先简化，并扩大到更长历史测试 |
| A 只在原题有效 | 可能是记忆答案或过拟合 | 不宣称泛化 |
| A 在边界题机械保守 | 判断范围过宽 | 检查归因和 scope |
| 相反证据改变文字，未改变行动 | 修正尚未进入决策闭环 | 检查 runtime 投影与行动选择 |
| 所有组原本就采取正确策略 | 此任务没有可识别的学习空间 | 报告无明显效果，重新选择有区别的任务 |

## 正式实验尚缺的信息

测试入口与受控 pilot 环境已建立。后续仍需更有学习空间的任务集、正式样本量、随机化或配对顺序、D／E 状态干预，以及统一的用户纠正／救援协议。小样本 pilot 不等于稳定成长结果；当前数据及配置限制见[结果报告](growth-pilot-report.md)。
