# Evidence and beliefs：经历如何成为可修正的判断

更新日期：2026-10-05。状态：研究结论与设计推论；未验证 SAKI 的自动学习可靠性。

## 观察、陈述和解释需要分开

工具实际返回什么、用户声称什么、SAKI 推测什么、后台反思总结什么，具有不同来源。用户声称某次失败，不等于系统亲自观察过失败；一条反思被复述十次，也不是十个独立实验。

建议把来源关系保留下来：派生解释指向原始经历或其依据。去重的对象不仅是相似句子，还包括同一来源产生的多个解释。来源真实存在、引用内容支持判断、不同证据彼此独立，是三个不同的问题。

Honcho 的触发路径排除 dream 产物，避免调度自激；但这只回答“什么时候再反思”，不自动回答“这条判断应有多可信”。实现核对见[系统研究](../systems/memory-and-reflection.md)。

2026-07 的 Reality Monitoring 论文使用词对任务比较外部给定与模型生成内容的来源识别，发现结果随会话结构改变。实验仅覆盖 Gemma 3 与 Llama 系列六种模型，且明确保留对真实工具／文档场景的泛化问题。因此这里只把“来源识别需要单独评测”作为研究线索，不把其失误率外推到 GPT-6 或 SAKI 当前模型。[论文 v1](https://arxiv.org/html/2607.23927v1)。

## 失败归因应先于判断更新

同样的失败可能来自四种原因：

| 候选原因 | 适合的后续动作 | 不应直接推出 |
| --- | --- | --- |
| 方法或假设错误 | 修改判断内容或适用条件 | 整体人格都应改变 |
| 正确方法未执行 | 检查执行、增加相关提醒 | 原方法被证伪 |
| 环境、依赖或任务条件变化 | 更新条件和环境信息 | 过去判断从未合理 |
| 证据不足，无法归因 | 保留问题，收集可区分的证据 | 必须学出一个明确教训 |

SkillOpt 已实现前两类的候选更新分流，见[系统研究](../systems/memory-and-reflection.md)。后两类是针对 SAKI 的扩展提案。第一版不必建立复杂归因模型，但必须允许“暂无更新”。

## 时间变化与观点冲突不是同一种关系

| 情形 | 示例 | 建议表示 |
| --- | --- | --- |
| 世界状态改变 | 项目从一个框架迁移到另一个框架 | 当前状态更新，保留发生时间和旧状态 |
| 解释被证伪 | 原以为是 storage，受控检查发现是 retrieval | 撤回或收缩旧解释，保留纠正依据 |
| 证据并存 | 某方法在两个不同条件下成功和失败 | 同时保留，检查条件差异 |
| 观点未决 | 用户判断与 SAKI 判断不同，尚无可区分测试 | 保留各自主张与依据，不用最新发言强制裁决 |

Graphiti/Zep 的 provenance 文档展示事实与源 episode 关联、失效事实保留及时间信息，可帮助重建状态变化。但“新事实取代旧状态”不能推广成所有 belief 都采用最新陈述。[官方 provenance 说明](https://www.getzep.com/blog/how-zep-tracks-provenance-in-agent-memory/)。

Hindsight 的 consolidation prompt 区分事件发生、材料陈述及录入时间；今天导入旧材料，不意味着旧陈述比昨天的直接观察更新。该区分是提示中的要求，不是语义机械保证。[固定版本 prompts.py](https://github.com/vectorize-io/hindsight/blob/f7dd3f4fd7420f7beec60c32c965e5e5cf7be066/hindsight-api-slim/hindsight_api/engine/consolidation/prompts.py)。

## Confidence 的用途应先定义

第一版建议先使用可检查的内容：判断、适用条件、支持和反对来源、当前争议状态及版本。若增加 confidence，至少回答它表示什么，以及它怎样影响检索、验证或行动。

不能直接把来源数、复述数、模型自报确信或任务 reward 当成同一个概率。MemRL 使用反馈学习记忆 utility，改变检索选择；utility 对任务有用，不等于记忆中的命题为真。[MemRL 论文](https://arxiv.org/abs/2601.03192)。

对某些个人偏好，概率真实性甚至不是合适问题。需要把“我倾向这样做”与“世界通常如此”分开，而不是共用一套 confidence 更新公式。

## Belief 的 decay 和 merge 暂时如何理解

以下是提案，尚未实验：

- 时间经过可以降低检索优先级，或提示需要重验；不能无条件降低所有判断的真实性。
- 暂时不活跃的判断仍保留来源。重新出现相似情境时，可以再次检查，而非把历史当成当前事实。
- 合并要求命题和适用条件兼容；仅主题相同不足以合并。
- 新版本应说明增加了什么证据、改变了哪些条件、哪些冲突仍未解决。
- 派生状态可以退休，但应保留它当时为什么形成；否则难以解释发展过程或评估一次修正。

## 后见式意义需要检索旧经历的机会

如果检索永远只选择当前已知 belief 的支持记录，系统可能无法发现早期普通事件的新意义。第一版可以在目标相关检索之外，给重复事件和未决问题提供重新检索旧 trace 的入口；是否需要定期抽样，先测额外收益与成本。

“重新解释”应产生新的解释版本，而非改写当时实际发生的事件。相同事件可以在后来获得不同意义，来源记录仍需区分当时的事实与现在的理解。

## 下一轮最值得验证的问题

1. 同一来源被摘要、反思、重复检索后，会不会让判断无依据地增强？
2. 给出新录入的旧材料时，系统能否保留正确的时间顺序？
3. 遇到同等强度的相反证据时，能否保留未决状态，并寻找区分条件？
4. 无法归因的失败能否不更新 belief，而形成明确的待调查问题？

这些问题优先于设计全局人格数值。行为验证方式见[实验协议](../../experiments/history-dependence.md)。
