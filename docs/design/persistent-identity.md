# Persistent identity：项目方向与关键问题

更新日期：2026-10-12。状态：用户方向、产品边界及批判分析；不是完整实现规格。

## 项目方向

用户进一步明确：让 agent 能进化、自己成长，是为了让它在长期使用中更好用。持续个体的方向服务于这一产品目标：过去的纠正、任务结果和共同项目经验应减少未来的重复错误与协作负担。

SAKI 探索成为一个跨会话持续存在的计算个体。LLM 提供认知计算，持久状态承载连续性，工具与 sandbox 提供环境交互。第一阶段需要证明：过去经历能够在新会话中成为行动改善的原因，而无需每次注入完整历史。

用户提出的核心约束：

- 经历影响解释、判断、偏好和行为；人格不由长篇角色 prompt 直接指定。
- Deep Self 保存长期状态；Runtime Self 只投影当前相关的小部分。
- 廉价记录普遍发生，反思有选择，深层变化缓慢；普通任务的能力和成本优先。
- attention 决定当前关注，不提前宣判经历永远无意义；支持后见式重新解释。
- 判断允许不确定和相反证据，并通过局部更新演进。
- shared history 超出用户 profile；SAKI 可以不同意用户，没有隐含的教育用户目标。
- 主动意图与执行权限分开；情绪和人格化文风暂不优先。

第一版聚焦 Experience、Belief、Reflection、Intention。长期身份还可能包含自传性记忆、价值、偏好、承诺、关系和目标，不应把这些全部归结为工程任务成功率。

## 产品边界：可由不同宿主承载的 Agent runtime

用户明确将 SAKI 定义为 Agent runtime／core。Web、Bot、TUI 和 GUI 都可以承载她；不同外壳不应分别实现一套 SAKI，也不应因展示方式变化而另造身份。

设计上区分三个边界：

- **长期身份状态**：未来持久保存的经历、判断、承诺与关系。它跨 session 和进程重启延续，不由某个界面的状态定义。
- **Session**：一个逻辑对话／工作的上下文与历史。私人助手可长期使用同一会话，开发场景可创建多个会话；新建 session 不等于创建新的 SAKI。
- **执行过程**：当前模型调用、工具执行、运行状态与结果事件。同一会话可以经历多次执行，执行结束不等于会话或身份结束。

核心负责会话与执行能力的统一语义，宿主负责输入来源、消息路由、展示及连接生命周期，并提供适用环境的配置和工具能力。单会话／多会话是会话选择与使用方式，后台运行／并发执行是另一组问题；不应把这些差异写进两套 Agent loop。

当前 Agent、Conversation 与前端已经按消息／事件分离，但现有 `Agent` 对象持有一个 Conversation，不能直接等同于完整的持久身份。已实现会话跨重启恢复，尚未实现独立 library 或共享长期身份；会话恢复也不代表长期身份机制已经存在。同一身份被多个进程同时使用时的状态协调，需在支持该场景前单独设计。

下一步先明确核心调用接口、状态归属、会话恢复与事件语义，再实现 session 管理；不为潜在宿主提前建立通用插件框架或多套运行内核。单会话／多会话需求见 [Session management](session-management.md)。

## 成长应带来哪些使用收益

以下是产品目标的具体化，尚非已经取得的结果：

- 用户纠正过的问题，在相似情境中较少再次发生。
- 成功方法能迁移到新任务，失效方法能被修正，减少无效尝试。
- 共同项目的背景、决定和未完成承诺能延续，减少重复解释。
- 已明确的协作习惯能影响执行，需求改变时能够重新适应。
- 重复问题可以被主动发现并提出有用的下一步，减少用户逐项推动。

这些收益需要同时考虑用户投入、任务质量、成本、延迟和行为稳定性。只证明 SAKI 变得不同，尚不能证明更好用；每次都迎合用户也不能代替可靠判断。

## 对原设计的批判

### 行为依赖历史，是必要起点，但成功标准还不够强

检索一条过去记录，也能产生 `same model + different history = different behavior`。这足以证明某个历史通道起作用，却不能单独证明形成了稳定判断、偏好或个体性。

需要分别检验：经历有没有被保存；保存状态有没有影响行动；影响能否迁移到未见任务；遇到反例能否收缩或修正；任务质量与用户负担是否改善。详见[实验协议](../experiments/history-dependence.md)。

### 工程经验、事实判断与价值偏好不是同一种更新

一次 regression 可以支持“类似改动应先定位原因”，未必支持“SAKI 整体风险承受能力下降”。局部失败推广成全局人格，可能只是过度概括。任务成绩可以验证某项技能，却不能自动决定她应该喜欢什么、如何对待关系或持有什么价值。

建议先记录带适用条件的判断，再观察它是否跨场景反复影响行为。人格变量是否有额外解释力，留给长期实验。

### 小数值变化不一定意味着行为上的小变化

`confidence -0.03` 或 `risk_tolerance -0.005` 没有天然的测量尺度。进入 prompt 后，模型也可能放大、忽略或非线性解释这些数字。“slow variable”需要从更新频率、修改范围与实际行为变化检验，不能仅由 delta 很小来保证。

这不是禁止 confidence；需要先明确它是概率、主观确信还是策略权重，并说明怎样校准、怎样影响行动。

### 保存所有经历，与廉价和可检索之间仍有取舍

不做 binary delete filter 是合理方向，但完整永久留存会产生存储、索引和重解释成本。只存摘要又可能不可逆地丢失未来有意义的细节。

第一版可以先保存工具和对话已经产生的原始 trace，注意力标签只影响检索与反思。以后制定容量、压缩或淘汰策略时，必须明确哪些内容会失去可恢复性；不能把“fast decay”同时用来指关注下降和原文删除。

### 保持状态不能保证模型迁移后的行为连续

新模型可能以不同方式解释同一判断。身份连续性在工程上至少需要状态 lineage、历史版本与迁移后的行为回归；不能把“状态仍在”直接等同于“判断方式完全延续”。分叉后的 A/B 应共享祖先，却是两个独立演进的状态分支。

### Belief 不会自动生成目标和 agency

“知道某种做法更可靠”与“自己决定调查一个问题”之间，还缺目标选择、优先级、时间和权限的机制。第一阶段可让 Intention 显式表达建议的下一步；持续自主行动另设实验，不依靠后台反思数量冒充主动性。

## 当前研究结论

第一阶段的问题是：**经历能否形成有来源、有适用条件、可修正的判断，并在有限上下文中改善实际行动、减少用户干预？** 身份与人格仍是长期探索方向；第一阶段的产品验收以长期使用收益为中心，不要求先证明完整个体性。

已有实践的证据见[系统研究](../research/systems/memory-and-reflection.md)，评价边界见[评测研究](../research/evaluation/history-to-behavior.md)。目前没有把上述建议批准为实现决策，也没有证明完整个体性或机器意识。
