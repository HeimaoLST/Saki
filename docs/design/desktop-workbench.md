# Nagi 工作台：视觉语言与交互原型

更新日期：2026-10-28。设计负责人：`agent:pm#mira`。任务 [#124](https://github.com/HeimaoLST/Saki/issues/124)，交付 PR [#125](https://github.com/HeimaoLST/Saki/pull/125)。

**设计提案，等待用户试用反馈。** [打开交互原型](previews/desktop-workbench.html)。第 07 版依据用户对原生界面「东西太多、层次不强」的反馈，以及参考 Magpie / yetone 作品的明确要求修订。HTML 是内存中的示例，不调用模型、不修改真实数据，不证明原生功能已经实现。页面外的窗口、外观、场景和模拟按钮只是设计审阅工具。

本版替代第 06 版的视觉与展示规则：默认三栏、深绿重点卡、书册装饰、大量等重边框、11px 辅助文字，以及旧的单执行槽／长期事项不在产品范围等阶段限制均不再作为开发要求。历史保留在 Git，不并列维护旧设计。产品定义以 [#138 的产品定义修订](https://github.com/HeimaoLST/Saki/blob/a76db4b33fc84eb2cb2c6608be95041e0496da92/docs/requirements/desktop.md) 和 [#157 的 MVP 交付](https://github.com/HeimaoLST/Saki/pull/157) 为范围依据；实现事实以 GUI 主责当前候选及 [desktop.md](desktop.md) 的明确版本记录为准。

## 设计依据

参考研究记录在 [Desktop interaction](../research/systems/desktop-interaction.md#magpie-与-cumora2026-10-28)。Magpie 的浅层表面、连续列表、弹出式控件和克制强调是主要参考；Cumora 提供联系人与气泡并存的参考。以下是 PM 的综合设计判断，不是 yetone 本人的设计宣言，也不是对参考产品的复制。

- 首屏先回答「和谁交流、对方是否在工作」，不把设置、状态筛选和执行日志一起展开。
- 用位置、分组、字号和间距表达主次；颜色只作补充。安静不等于小字、低对比或只有 hover 才发现入口。
- 联系人和对话属于 Nagi 的主线。工作区补充交流，事项有独立于消息与单次执行的生命周期。
- 保留 Nagi 的 mascot、左右气泡和少量苔绿；不用 Magpie 的鸟形标志、紫色品牌、供应商布局或 Cumora 的完整团队导航。

## 美学规则

| 层级 | 尺寸与形式 | 用途 |
| --- | --- | --- |
| 应用与联系人标题 | 16–19px，600 | 明确当前位置与对象；不用大号衬线标题竞争内容 |
| 事项详情标题 | 20px / 1.5，600 | 只在选中一件事后突出目标 |
| 正文／对话 | 14–15px；消息 15px / 1.8 | 主要阅读内容，正常字重 400 |
| 操作与行标题 | 操作 13px / 500；事项 14px / 550 | 保持可读；不靠字号缩小来塞入更多按钮 |
| 辅助文字 | 最低 12px / 1.5，400 | 日期、来源、状态补充；浅深色均测对比 |
| 间距 | 4 / 8 / 12 / 16 / 20 / 24 / 28px | 相关内容近，独立分区远；减少嵌套容器 |
| 头像 | 联系人 34px、页头 35px、空态 52px | 继续使用现有 mascot；字母头像只作示例 |
| 控件 | 普通操作至少高 32px；图标 32×32px；图形 17px | 有可访问名称、焦点与 pressed 反馈；工具栏不需要每个入口都套描边 |
| 容器 | 轻边界、8–13px 圆角；气泡约 15px | 表面区分用于组织；阴影只用于输入区轻分层、窗口和浮层 |

### 控件必须有不同的视觉职责

| 类型 | 表现 | 不能做的事 |
| --- | --- | --- |
| 当前主操作 | 实色填充，例如发送、补充要求、创建表单提交 | 同一区域堆叠多个大面积实色动作 |
| 导航／视图切换 | 当前项浅底或分段选中态，文字稳定 | 把联系人筛选做成三颗纵向全宽主按钮 |
| 下拉选择 | 浅底或明确下箭头；标签完整；键盘可用 | 只放一个看不出可点击的值 |
| 列表行 | 整行可点击、固定对齐、尾部箭头、hover/focus 状态 | 每行套卡片，再给卡片里的每个字段套按钮 |
| 次要工具 | 图标＋文字或标准图标按钮；tooltip 与可访问名称 | 仅在 hover 出现关键操作；用抽象符号代替关键动词 |
| 状态 | 图标／圆点＋明确文字；默认不是按钮 | 状态和操作使用相同描边；把成功颜色当作完成依据 |

## 三栏与工作详情

默认只展开联系人和对话；用户明确打开工作区时才出现第三栏。工作开始、完成、切换联系人和收消息均不强制打开。产品保存用户显式展开状态与宽度；HTML 刷新重置，不模拟持久化。

- 默认联系人 200px（可调 180–280），工作区 340px（可调 280–440），中间至少 480px 且宽于左右任一栏；分隔线各 1px。
- 1040px 应用画布默认约 200 / 496 / 340，剩余为边框／分隔线。宽度不足时先夹取实际右栏宽度，低于「左栏＋280＋480＋分隔线／边框」时转覆盖抽屉，不压缩文字。
- 两个分隔条支持拖拽和左右方向键，每次 10px；窄窗口的临时夹取不覆盖用户宽度偏好。原生继承 #184 的持久化、最小窗口及恢复行为，不另写布局状态系统。
- 左侧是联系人、搜索、一个范围选择器和「＋添加」。主区头部是身份／运行状态、历史、工作区和联系人设置；模型选择位于 composer。外观仍属应用级。
- 工作区展开时是非模态，主对话仍可操作；窄窗口覆盖时是模态，关闭／Escape 返回入口焦点。
- 中间消息与右侧详情各自纵向滚动。打开详情不清空草稿，不重置主对话阅读位置。

## 工作区：每次只看一个层级

### 事项概览

只展示事项行：标题、一行近况、管理状态、可选计划日期和进入箭头。以一个选择器查看未结束／已完成／全部；不常驻六颗状态按钮。需要用户处理的事项有轻提醒底色和具体缺口，正常工作用图标／文字。最近完成单独展示一条可追溯成果，不复述全部执行。

点击事项进入详情并替换概览，返回恢复原视图与行焦点。联系人切换时只展示该联系人的事项；空态引导记下一件事，不放虚构的已完成内容。

### 事项详情

阅读顺序固定：返回 → 管理状态／正在执行时的停止入口 → 事项名称与目标 → 真实需要处理的问题 → 已有成果 → 要求与完成依据 → 按需展开的执行记录／计划管理。

- 有成果时，文件行本身就是阅读入口，含「打开阅读」及箭头，不再另放一颗重复的「查看成果」主按钮。
- 需要选择时，「补充要求」带事项上下文回到 composer；保留原对话。待办事项可以「开始处理」。停止作用于本次执行，不藏到多层日志中。
- 要求逐条显示已满足／未核实和依据。`2 / 4` 是要求数量，不是运行进度百分比。缺少依据时不能猜成功，也不因此给所有完成新增人工审批关卡。
- 执行日志默认收起；显示真实工具与输出摘要，不推测隐藏思考，不铺成聊天气泡。
- 一次执行完成后仍有要求未满足，显示「本次执行已结束，事项还未完成」。不会生成伪聊天回复，不自动移入 Done。
- 文件读取／打开失败应保留事项，给失败原因与重试；成功、空内容、过大内容的原生行为沿用现有 reader。本 HTML 只展示固定的阅读样本。

### 轨迹、看板与日程

「轨迹」是这个联系人跨时间的交办、补充、等待和成果，能回到相同的事项；不是执行日志的改名。当前示例仅用有限节点说明层次，生产要消费实际历史，不能根据最新状态伪造过去事件。

看板／日程从工作区底部明确进入较宽阅读浮层。看板按 Todo / Doing / Done 分组，窄视口纵向排列；不在 340px 侧栏内挤三列。日程按计划日期分组，未安排日期的事项保留；计划日期不是自动触发。看板与概览共享事项数据。原型不实现自动调度、多人协作或 Runtime 业务编排。

## 消息、富文本与输入

- 用户在右、Agent 在左，气泡按真实消息归属；长回复不擅自拆成多条。保留中文段落、列表、表格、图表、来源和复制。
- 表格单元格换行，不以横向滚动作为默认阅读方式；复杂内容可展开到较宽阅读面。若原生尚不支持图表，只保留已实现内容，不能为符合截图伪造图表。
- 工具执行与消息独立。工作期间有消息就显示消息，无消息也能在页头／工作区看工作状态；执行结束不增加消息未读。
- 联系人各自保留草稿；Enter 发送、Shift+Enter 换行、composition 中 Enter 不发送。真实 IME 验收仍属 #114；浏览器 key handler 不证明原生输入可靠。
- 连接异常保留草稿并说明下一步；设置不反复出现在空态和页头两个同等位置。模型切换及继续／干预按现有 Runtime/GUI 契约消费，HTML 下拉只演示位置。
- 原型「发送」只把文本加入页面，不调用模型。模拟执行结束不改变消息条数，也不满足尚未核实的要求。

## 动效与焦点

**设计参数，非参考产品实测值**：hover/pressed 120ms；面板出现 140ms opacity 与 6px 位移；不动画正文宽度或用装饰动画吸引注意。`prefers-reduced-motion` 时取消动画。打开深层阅读后 Escape 只关最上层；焦点返回真实入口。非模态工作区不锁住对话；模态抽屉使用焦点约束。状态变化只用一条简短公告，不重复播报整段正文。

## 开发交接与验收

PM 负责此原型、文案、视觉约束与设计复核；GUI 主责按独立需求实施 Go/MyGo，模块测试、真实窗口与可访问性由实际实现验证。#184 的布局修复保持冻结，本版不混入其已审候选。先实现导航层级与控件样式，再接同一套事项状态；不另建第二套 store 或 Runtime 事实来源。

| 验收 | 可观察结果 |
| --- | --- |
| 首次打开／恢复 | 首次工作区关闭；恢复用户显式偏好；中间始终为主要交流面 |
| 1040、宽屏、720 | 左右可调；中间不被压至 480 以下；720 使用覆盖抽屉；无页面横向滚动 |
| 不同操作层级 | 可分辨当前选择、主要动作、次要动作和静态状态；普通文字至少 12px |
| 概览 → 详情 → 返回 | 不同时铺开列表与全详情；返回到同一筛选／事项，草稿不变 |
| 完成依据 | 部分要求满足时不能显示整项已完成；Done 能访问真实成果与依据 |
| 工作／消息分离 | 无消息执行结束不追加回复；工作中交流不取消执行；失败有具体入口 |
| 成果阅读 | 正常渲染富文本；可复制；Escape 关闭阅读回到文件行，侧栏不跟着消失 |
| 联系人切换 | 不串事项、历史或草稿；空列表与无匹配搜索有可理解的状态 |
| 浅／深色与键盘 | 对比独立检查；Tab 焦点可见；分隔条可键盘调节；reduced-motion 无位移动画 |
| 边界 | 新增／归档／取消等已有产品能力不因视觉精简而被移除；移入次级菜单仍须可发现和测试 |

**原型覆盖限制**：没有真实持久化、网络、模型、文件系统、原生 IME、权限或断连恢复。取消／归档管理与全部错误矩阵未在 HTML 模拟，生产必须保留已有能力。调度、跨联系人协作不在本次视觉改造范围。HTML 的一次浏览器通过不等于 Nagi MVP 验收。
