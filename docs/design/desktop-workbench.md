## 设计依据

参考研究记录在 [Desktop interaction](../research/systems/desktop-interaction.md#magpie-与-cumora2026-10-28)。Magpie 的浅层表面、连续列表、弹出式控件和克制强调是主要参考；Cumora 提供联系人与气泡并存的参考。以下是 PM 的综合设计判断，不是 yetone 本人的设计宣言，也不是对参考产品的复制。

- 首屏先回答「和谁交流、对方是否在工作」，不把设置、状态筛选和执行日志一起展开。
- 用位置、分组、字号和间距表达主次；颜色只作补充。安静不等于小字、低对比或只有 hover 才发现入口。
- 联系人和对话属于 Nagi 的主线。工作区补充交流，事项有独立于消息与单次执行的生命周期。
- 保留 Nagi 的 mascot、左右气泡和少量苔绿；不用 Magpie 的鸟形标志、紫色品牌、供应商布局或 Cumora 的完整团队导航。

### 六项实施原则

| 原则 | Nagi 必须出现的行为 | 验收观察 |
| --- | --- | --- |
| 围绕对象组织 | 联系人 → 对话／交办 → 事项 → 成果；运行状态与管理状态分开 | 用户能指出当前联系人、事情进展、下一步动作和成果入口 |
| 连续排版 | 联系人／事项行使用稳定的标题、近况、状态、辅助信息对齐；卡片只承载独立提醒或成果 | 正常、等待、失败、已完成样本均无重复卡片套层或等重按钮墙 |
| 控件可发现 | 操作有动词；选择器有当前值和下箭头；进入行有箭头；静态状态不冒充动作 | 不移动鼠标也能识别入口；hover、pressed、键盘焦点仍可辨 |
| 保留上下文 | 打开／关闭事项、成果、设置后恢复对应入口、筛选与阅读位置 | 中途写草稿，再往返详情／阅读，内容与归属不变；Escape 只退一层 |
| 局部个性与真实近况 | 头像、名字和少量强调色体现身份；近况来自现有执行、事项及问题数据 | 多项并行显示数量或可确认的摘要；未知时明确未知，不伪造“思考中”、进度或消息 |
| 细节一致 | 统一字号、语义配色、图标视觉重量、间距和反馈；浅深色分别核验 | 中文长文、长标题、表格、错误及紧凑窗口可读，关键操作无裁切 |

采用的是上述原则，不要求复制参考产品的小字号、品牌、全部功能或每一项动效。装饰性动画不得阻塞首批可用性改进；已有焦点、按压、状态反馈必须保留，必要动效尊重系统减少动态效果设置。

## 美学规则

| 层级 | 尺寸与形式 | 用途 |
| --- | --- | --- |
| 应用与联系人标题 | 16–19px，600 | 明确当前位置与对象；不用大号衬线标题竞争内容 |
| 事项详情标题 | 20px / 1.5，600 | 只在选中一件事后突出目标 |
| 正文／对话 | 14–15px；消息 15px / 1.8 | 主要阅读内容，正常字重 400 |
| 操作与行标题 | 操作 13px / 500；事项 14px / 550 | 保持可读；不靠字号缩小来塞入更多按钮 |
| 辅助文字 | 最低 12px / 1.5，400 | 日期、来源、状态补充；浅深色均测对比 |
| 间距 | 4 / 8 / 12 / 16 / 20 / 24 / 28px | 相关内容近，独立分区远；减少嵌套容器 |
| 头像 | 联系人 34px、页头 35px、空态 52px | 继续使用现有 mascot；字母头像只作示例 |
| 控件 | 普通操作至少高 32px；图标 32×32px；图形 17px | 有可访问名称、焦点与 pressed 反馈；工具栏不需要每个入口都套描边 |
| 容器 | 轻边界、8–13px 圆角；气泡约 15px | 表面区分用于组织；阴影只用于输入区轻分层、窗口和浮层 |

### 控件必须有不同的视觉职责

| 类型 | 表现 | 不能做的事 |
| --- | --- | --- |
| 当前主操作 | 实色填充，例如发送、补充要求、创建表单提交 | 同一区域堆叠多个大面积实色动作 |
| 导航／视图切换 | 当前项浅底或分段选中态，文字稳定 | 把联系人筛选做成三颗纵向全宽主按钮 |
| 下拉选择 | 浅底或明确下箭头；标签完整；键盘可用 | 只放一个看不出可点击的值 |
| 列表行 | 整行可点击、固定对齐、尾部箭头、hover/focus 状态 | 每行套卡片，再给卡片里的每个字段套按钮 |
| 次要工具 | 图标＋文字或标准图标按钮；tooltip 与可访问名称 | 仅在 hover 出现关键操作；用抽象符号代替关键动词 |
| 状态 | 图标／圆点＋明确文字；默认不是按钮 | 状态和操作使用相同描边；把成功颜色当作完成依据 |

## 三栏与工作详情

默认只展开联系人和对话；用户明确打开工作区时才出现第三栏。工作开始、完成、切换联系人和收消息均不强制打开。产品保存用户显式展开状态与宽度；HTML 刷新重置，不模拟持久化。

- 默认联系人 200px（可调 180–280），工作区 340px（可调 280–440），中间至少 480px 且宽于左右任一栏；分隔线各 1px。
- 1040px 应用画布默认约 200 / 496 / 340，剩余为边框／分隔线。宽度不足时先夹取实际右栏宽度，低于「左栏＋280＋480＋分隔线／边框」时转覆盖抽屉，不压缩文字。
- 两个分隔条支持拖拽和左右方向键，每次 10px；窄窗口的临时夹取不覆盖用户宽度偏好。原生继承 #184 的持久化、最小窗口及恢复行为，不另写布局状态系统。
- 左侧是联系人、搜索、一个范围选择器和「＋添加」，底部只有统一「设置」入口。主区头部是身份／运行状态、历史、工作区与「联系人资料」快捷入口；模型选择位于 composer。设置页面的导航与作用范围见下节。
- 工作区展开时是非模态，主对话仍可操作；窄窗口覆盖时是模态，关闭／Escape 返回入口焦点。
- 中间消息与右侧详情各自纵向滚动。打开详情不清空草稿，不重置主对话阅读位置。

## 统一设置页面

**用户已明确的设计方向；统一设置路由在 714 已有实现，原生验收范围见 [#200 comment 6513948407](https://github.com/HeimaoLST/Saki/issues/200#issuecomment-6513948407)。** 设计基线 `f3d8485` 当时仍有应用外观、联系人 Settings 与连接配置浮层；714 已有统一设置入口、分类路由和连接/联系人页面接线，但不代表本节全部视觉、交互与可访问性已经通过，也不能据此宣称 714 已完全符合 v08。它属于 GUI 应用层，不新增 Agent Runtime 能力，也不改配置格式或执行会话契约。

### 页面与入口

- 工作台侧栏底部固定「设置」图标＋文字。进入后整块应用内容切换为设置页面：原联系人列表、搜索、添加、对话和工作区退出视图及键盘顺序；左侧仅有设置分类，右侧为当前内容。左上固定「返回工作台」。页面没有遮罩、浮层阴影、背景置灰或居中对话框外壳，不另开系统窗口、不强制最大化。
- 设置页有「设置」标题、分类导航和内容区，不能并列保留联系人导航与设置导航。分类直接切换同一页面内容。第一版为「外观」「连接与模型」「联系人资料」「高级」；只容纳已有能力，不添加占位开关或未来功能菜单。
- 聊天空态和页头不再重复放 Settings。联系人快捷入口明确叫「联系人资料」，直接定位同一设置页面中的当前联系人；连接错误中的「连接设置」直接定位连接分类及具体错误。高级诊断也在同页展开，不能套第二层设置弹窗。
- composer 的会话模型选择保留为上下文动作，显示它作用于哪段对话／事项；修改全局连接默认值与修改当前会话模型不可互相替代。

### 分类与作用范围

| 分类 | 内容与组织 | 生效语义 |
| --- | --- | --- |
| 外观 | 跟随系统／浅色／深色，预览卡同时有名称、边界与选中标记；沿用既有主题，不新增主题 ID | 选择立即生效并显示轻量反馈；保留既有持久化和读取错误语义 |
| 连接与模型 | 顶部摘要显示当前生效配置；表单包含协议、地址、密钥、默认模型和工作目录；容量与执行限制按需展开 | 保存不打断工作；保存成功但未应用要明确显示待应用；运行中不能应用时说明原因；测试使用当前表单值且独立显示结果 |
| 联系人资料 | 明确标题「某联系人 · 资料」，仅在此分类提供编辑对象选择；保留该联系人全部已有字段、profile、归档／恢复等能力；危险或低频动作放次级区 | 仅改当前联系人；资料默认值适用于新会话，已有会话快照不被重写；保存与错误反馈在本页 |
| 高级 | 已有启动信息、路径、版本和诊断，分组且可展开；真实失败附可执行的恢复入口 | 只展示已经核实的事实；未检测、未启动与确定缺失分开，不把空路径写成“未找到 helper” |

设置页面统一表单层级、按钮位置和反馈规则，保留不同动作的真实生效时机。外观的即时选择无需多余保存按钮；连接继续区分表单草稿、已保存值和当前生效值。密钥沿用现有存储及隐藏方式，不新建凭据系统。

### 表单、布局与返回

- 1040／1380 画布：左侧设置分类约 200px；右侧内容弹性占剩余空间，表单正文最大约 720px，左右留白 24–40px。分类与内容以细分隔线和留白组织，不为每一项叠卡片。页面标题 24px，分类与表单正文 14–15px，帮助文字至少 13px；控件高度遵循既有至少 32px 规则。
- 窄至 720px 时分类收窄至约 156px，或改为内容上方可换行的导航，表单单列；密钥、长 URL、路径和错误提示不得撑出横向滚动。减少留白而不缩小正文。不回退为弹窗或遮挡表单的抽屉。
- 可编辑项有可见标签、字段附近的帮助及错误；错误不只出现在 toast。保存／应用／测试有忙碌、失败、成功状态，错误保留输入。只有适用动作可点击，禁用动作旁给出原因；首用未配置不显示无效容量重试。
- 分类切换保留未保存的表单草稿，并把新分类的标题与首项置于可见位置；联系人草稿按编辑对象保留，切换 A→B→A 不丢编辑，设置中的编辑对象不暗中切换返回工作台的联系人。返回工作台也保留本次应用生命周期中的设置草稿；再次进入明确标记未保存，提供保存及放弃动作。未保存草稿不冒充已写入磁盘；退出应用的行为沿用既有约定。短表单的底部操作行与正文属于同一页面，不绘制弹窗式 footer。
- 进入设置临时隐藏工作区，保留其显式开闭、宽度、当前事项和滚动位置；不因此修改工作区持久偏好、不取消正在执行的任务。返回时恢复同一联系人、对话、草稿、消息滚动、事项／成果上下文和原入口焦点。非页面重载不要重建会话或发模型请求。
- `Cmd+,` 打开设置；「返回工作台」回到原先上下文。Escape 只关闭当前下拉等临时层，不把整页设置当弹窗关闭。设置不锁焦点，键盘顺序为返回→分类→当前内容，当前分类和标题可被辅助技术识别。

### 设置专项验收

| 场景 | 可观察结果 |
| --- | --- |
| 首次进入与快捷入口 | 统一设置入口进入完整页面，联系人列表不再出现或接收焦点；外观、联系人资料、连接错误进入同一页面且分类正确；无遮罩或嵌套设置弹窗 |
| 工作中往返 | 后台工作继续；恢复原联系人、草稿、阅读位置、事项与工作区开闭；输入焦点回原入口 |
| 未保存编辑 | 分类切换和工作台往返不丢输入；未保存标记准确；放弃只影响本设置表单，不清空聊天草稿 |
| 连接三种状态 | 表单／保存／生效值可区分；保存不暗中切换正在运行的会话；应用受限有解释；测试失败可原地修正 |
| 联系人范围 | 修改 A 不影响 B，编辑对象切换不丢各自草稿且不改工作台返回对象；新会话使用新默认，旧会话快照保持；既有归档／恢复能力仍可达 |
| 布局与键盘 | 1380／1040／720、浅深色均可读；没有横向滚动；Tab、Cmd+,、返回可用，Escape 不误退整页 |

原型演示范围是页面结构、外观、连接表单状态、联系人名称／用途与上下文往返。生产实施必须保留原生完整字段、真实测试和恢复行为；不能用原型的示例成功结果替换真实检查。

## 工作区：每次只看一个层级

### 事项概览

只展示事项行：标题、一行近况、管理状态、已有真实计划日期（如有）和进入箭头。以一个选择器查看未结束／已完成／全部；不常驻六颗状态按钮。需要用户处理的事项有轻提醒底色和具体缺口，正常工作用图标／文字。最近完成单独展示一条可追溯成果，不复述全部执行。

筛选映射属于本轮实施要求：「未结束」包含所有未归档且非 completed/canceled 的事项，包含等待用户和需要处理；「已完成」仅包含未归档 completed；「全部」包含取消与归档，行内明确标记并保留重开／恢复入口。不能直接把旧 active 改名为「未结束」而遗漏 waiting/attention。这里只改展示投影，不改持久状态枚举或既有动作条件。

点击事项进入详情并替换概览，返回恢复原视图与行焦点。联系人切换时只展示该联系人的事项；空态引导记下一件事，不放虚构的已完成内容。

概览／详情是短生命周期的显示状态。返回概览不能靠清空持久 SelectedIssueID 触发业务回退；筛选、滚动锚点和返回目标按联系人隔离。归档、取消、恢复、重开、编辑和手动完成放在有文字的管理入口中，保持可发现；正在执行时的停止仍显式呈现。

### 事项详情

阅读顺序固定：返回 → 管理状态／正在执行时的停止入口 → 事项名称与目标 → 真实需要处理的问题 → 已有成果 → 要求与完成依据 → 按需展开的执行记录／计划管理。

- 有成果时，文件行本身就是阅读入口，含「打开阅读」及箭头，不再另放一颗重复的「查看成果」主按钮。
- 需要选择时，「补充要求」带事项上下文回到 composer；保留原对话。待办事项可以「开始处理」。停止作用于本次执行，不藏到多层日志中。
- 要求逐条显示已满足／未核实和依据。`2 / 4` 是要求数量，不是运行进度百分比。缺少依据时不能猜成功，也不因此给所有完成新增人工审批关卡。
- 执行日志默认收起；显示真实工具与输出摘要，不推测隐藏思考，不铺成聊天气泡。
- 一次执行完成后仍有要求未满足，显示「本次执行已结束，事项还未完成」。不会生成伪聊天回复，不自动移入 Done。
- 保留现有显式「标记完成」能力及其运行／未定请求限制。用户主动标记完成时显示「用户标记完成」与实际依据，未核实要求保持原状；不冒充系统逐项验证通过，不添加一套强制人工审批。上述“不能自动 Done”约束自动推断，不禁止用户已有的明确决定。
- 文件读取／打开失败应保留事项，给失败原因与重试；成功、空内容、过大内容的原生行为沿用现有 reader。本 HTML 只展示固定的阅读样本。

### 轨迹、看板与日程

「轨迹」是这个联系人跨时间的交办、补充、等待和成果，能回到相同的事项；不是执行日志的改名。当前示例仅用有限节点说明层次，生产要消费实际历史，不能根据最新状态伪造过去事件。

看板／日程从工作区底部明确进入较宽阅读浮层。看板按 Todo / Doing / Done 分组，窄视口纵向排列；不在 340px 侧栏内挤三列。日程按计划日期分组，未安排日期的事项保留；计划日期不是自动触发。看板与概览共享事项数据。原型不实现自动调度、多人协作或 Runtime 业务编排。

**本轮实施边界**：先交付现有壳层、事项导航和成果阅读的改进，不要求把 HTML 的轨迹／看板／日程示例全部实现。33fc398 中事项没有计划日期字段，不能以 UpdatedAt 代替；未记录的历史不能从当前状态倒推。此类新数据能力后续单独定义，不放空入口、示例事件或假成果来填充原生页面。

## 消息、富文本与输入

- 用户在右、Agent 在左，气泡按真实消息归属；长回复不擅自拆成多条。保留中文段落、列表、表格、图表、来源和复制。
- 表格单元格换行，不以横向滚动作为默认阅读方式；复杂内容可展开到较宽阅读面。若原生尚不支持图表，只保留已实现内容，不能为符合截图伪造图表。
- 工具执行与消息独立。工作期间有消息就显示消息，无消息也能在页头／工作区看工作状态；执行结束不增加消息未读。
- 联系人各自保留草稿；Enter 发送、Shift+Enter 换行、composition 中 Enter 不发送。真实 IME 验收仍属 #114；浏览器 key handler 不证明原生输入可靠。
- 连接异常保留草稿并说明下一步；设置不反复出现在空态和页头两个同等位置。模型切换及继续／干预按现有 Runtime/GUI 契约消费，HTML 下拉只演示位置。
- 模型入口靠近 composer，但继续打开现有真实会话选择界面；尚未绑定会话时明确使用连接默认值，不模拟立即生效。Issue model 与 conversation model 的目标不能混用。
- 补充要求继续走已有定向派发和补充账本；不能把原型往输入框加前缀的做法直接替换生产流程。保留待发、已接纳、unknown、自动继续和核对恢复；unknown 不提供盲目重发。
- 原型「发送」只把文本加入页面，不调用模型。模拟执行结束不改变消息条数，也不满足尚未核实的要求。

## 动效与焦点

**设计参数，非参考产品实测值**：hover/pressed 120ms；面板出现 140ms opacity 与 6px 位移；不动画正文宽度或用装饰动画吸引注意。`prefers-reduced-motion` 时取消动画。打开深层阅读后 Escape 只关最上层；焦点返回真实入口。非模态工作区不锁住对话；模态抽屉使用焦点约束。状态变化只用一条简短公告，不重复播报整段正文。

## 开发交接与验收

PM 负责此原型、文案、视觉约束与设计复核；GUI 主责按独立需求实施 Go/MyGo，模块测试、真实窗口与可访问性由实际实现验证。#184 的布局修复保持冻结，本版不混入其已审候选。先实现导航层级与控件样式，再接同一套事项状态；不另建第二套 store 或 Runtime 事实来源。

已采纳 [GUI 可行性核对](https://github.com/HeimaoLST/Saki/issues/124#issuecomment-6460603751)：固定原生基线为 33fc398，保留完整联系人配置、归档／恢复、新对话、历史搜索、对话与事项各自 Stop、运行容量、pending/unknown 核对、连接保存／应用／测试、资料快照与真实成果来源。Reader 继续关联联系人／事项／执行／会话／task／连接代次，复用现有 Markdown、精确复制和空／大／失败内容处理；仅改变入口与返回时优先使用局部返回目标，先不建立通用弹层框架。实时负责人、依赖和交付顺序统一由 #140 与实施 issue 管理，不在本文另建进度表。
