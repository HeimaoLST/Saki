# Nagi 工作台：内容优先的视觉与交互规范

更新日期：2026-11-03。设计负责人：`agent:pm#mira`。任务 [#124](https://github.com/HeimaoLST/Saki/issues/124)、[#216](https://github.com/HeimaoLST/Saki/issues/216)、[#257](https://github.com/HeimaoLST/Saki/issues/257)、[#273](https://github.com/HeimaoLST/Saki/issues/273)。[打开交互原型](previews/desktop-workbench.html)。

**实施指导，原生效果仍需验收。** 本规范把用户本轮“内容优先、集中输入、图标可发现、普通流程非模态”的要求落到现有工作台，不改变 Runtime 协议、产品能力或 store。HTML 是设计参考和交互样本，不调用模型、不修改真实数据，也不证明原生功能已经实现。

## 官方基线、版本适用与偏离

- 官方参考：[MyGo docs](https://mygo.egoist.dev/docs)（Native UI、Button、Toolbar、Text、Styling）及其组件语义。用户已要求升级到最新稳定版；[#98](https://github.com/HeimaoLST/Saki/issues/98) 当前按官方 v0.7.3 由 GUI 主责核对和采用。实际 `go.mod` 版本用于复现，不是长期冻结；旧 0.4.9 只作为历史／回滚输入，本规范不以它作为适配约束。不得把官网 API 当成未核对的实现能力。
- 采纳 [#220 完整研究](https://github.com/HeimaoLST/Saki/issues/220#issuecomment-6524047040) 的 1–8 项及格方向：正文优先、输入边界清楚、主动作与作用域明确、少量可辨字体角色、紧凑工具可发现、稳定导航／返回、长内容／窄窗可读、浅深色及状态可辨；9–10 的边界与图标光学精修后置，不阻塞首批。
- 先按核定的最新稳定版 Button/Toolbar/Text/布局能力和主题角色做朴素、统一的及格实现，再评估精修；不为兼容旧版自造框架。icon-only 操作必须有可访问名称、tooltip、焦点与按压反馈；hover 才出现的工具不应成为唯一发现方式。
- 必要偏离必须记录“适用组件／依据／不可替代缺口／最小兼容做法”。若核定版本缺少不可替代的 API，交 GUI 主责复用 [#98](https://github.com/HeimaoLST/Saki/issues/98) 评估；不擅自全量升级，也不把其他设计工作全部堵在升级上。
- 字体采用固定四档受控语义（12/13/14/16），不再保留 20px 大标题约束；实现按主题、官方示例和实际渲染校准字重与留白，不机械覆写真实消息内容。本轮是依据用户“字号偏大、排布松粗”反馈的首轮 Nagi 试样；Qoder/Codex 参考设置未能通过工具授权读取，不写成已实测参数，待可用的真实字号/缩放反馈再校准。
- 语义配色采用 [#221 正式报告](https://github.com/HeimaoLST/Saki/issues/221#issuecomment-6524653785) 的人工适配值；[PM 复核](https://github.com/HeimaoLST/Saki/issues/221#issuecomment-6524790831) 可作承接引用。Adobe 原始五色只记来源／方法，不等于 UI 色板；92 对静态对比边界见下，最终原生颜色与组件状态仍待验证。

## 设计方向

内容是主角，操作靠近对象，结构靠位置、字号、留白和少量语义色建立。联系人和对话保持主线；事项、历史、资料和成果是同一工作台的不同层级，不用大按钮墙或弹窗抢占注意力。

六项原则：

| 原则 | 必须出现的行为 |
| --- | --- |
| 围绕对象组织 | 联系人 → 对话／交办 → 事项 → 成果；运行状态与管理状态分开 |
| 连续排版 | 联系人、事项、历史行使用稳定对齐；卡片只承载独立提醒或成果 |
| 控件可发现 | 操作有明确图标／动词、可访问名称和 tooltip；静态状态不冒充动作 |
| 保留上下文 | 详情、设置、阅读返回原入口、筛选、草稿和阅读位置 |
| 消息与工作分开 | 一次执行可以没有聊天消息；工具活动不生成伪回复 |
| 细节一致 | 同一层级使用同一字号、字重、焦点和反馈；浅深色分别核验 |

### 图表、文案与解释

- 图表只表达当前任务需要的信息，不增加额外网格、刻度、图例或标注堆叠；没有现成功能时不新增图表。
- 界面文案使用直接、准确的常用词，不造概念，不用夸张口语、营销腔或重复解释。真实模型、协议、文件路径和用户／Agent 原文保持正确可读。
- 删除不帮助当前操作的解释文案；空态只留事实或下一步，不用泛泛宣传；通用 › 外观用现有官方 Segmented 做三选一（32 高、控件 13），只显示 System／Light／Dark，辅助说明 12，不写“语义适配”等实现说明。必要错误、有效模型、保存／取消作用域、容量和恢复入口仍清楚可见。
- 不使用装饰性代码面包屑、章节序号或标题上眉标；必要文件路径保持原文和可访问性。正文中的示例阅读小标题属于内容，不当作界面装饰删除。

## 界面语言、术语与文案

### 语言、作用域与命名

- 初期只支持简体中文（`zh-Hans`）和英文（`en`）。默认跟随系统：系统首选属于 `zh-Hans` 家族（包括 `zh-CN`、`zh-SG` 等）时显示简体中文；`zh-Hant`／`zh-TW`／`zh-HK` 不自动判为简中，默认显示英文，繁体系统用户可手动选择简体中文。这是已接受的首发限制。
- Settings 的 `通用 / General` 分类包含 `外观 / Appearance` 与 `语言 / Language` 两组。语言选项为「跟随系统（当前：简体中文） / System (currently English)」「简体中文」「English」；每种语言名用自身语言书写。切换立即生效，保留草稿、焦点、滚动位置、已打开详情和设置分类；重启后保持所选语言。若只有部分系统菜单需重启才切换，在语言组下方用一行事实说明。
- 采用 MyGo 内置 i18n 路线：ARB 风格翻译、ICU MessageFormat、CLDR 复数／语言匹配及生成函数，按实际 API 生成和读取；不引入 go-i18n、另一套 locale 框架或第二份语言权威，也不另写第二套语言判定算法。当前只记录设计约束，框架接入、`SetLocale` 持久化、菜单和伪语言验证仍由 GUI 实现并另验。
- 界面语言不修改 system／instructions、联系人职责、会话快照或 Agent 的回复语言；不翻译用户／Agent 原始内容、已有联系人名称、模型/provider 名称、协议值、文件路径、代码和工具原始输出。原始诊断保留原文，面向用户的主文案另给“发生了什么 + 怎么办 + 入口”。
- 新 UI 的品牌名一律为 **Nagi**；改软件名不等于替换用户内容、对话或事项文本、或联系人名。内部数据目录 `Application Support/Saki/`、bundle ID、`SAKI_*`、`Saki-runtime` 及已有联系人名 `Saki` 不改。软件名 Saki 只在诊断中以 Saki Runtime 出现；用户／联系人原文中的 Saki 按上一条保持原样。

### 术语定稿

| 中文 | English | 使用边界 |
| --- | --- | --- |
| 联系人 | Contact | 长期联系人对象，不翻译已有联系人名 |
| 对话 | Chat | 普通交流上下文 |
| 事项 | Task | 用户要完成的一件事；普通 UI 不再写 Issue |
| 执行 | Run | 一次运行时执行；普通 UI 不再写 Execution |
| 要求 | Requirement | 事项的明确要求 |
| 补充要求 | Follow-up | 对事项的后续补充，不另造任务 |
| 资料 | Context | composer 中附带的资料 |
| 结果 | Result | 执行或事项的可核对成果 |
| 通用 | General | Settings 一级分类 |
| 外观 | Appearance | General 下的主题设置 |
| 语言 | Language | General 下的界面语言设置 |
| 事项 | Tasks | 工作区顶部切换标签「事项 / Tasks」 |
| 对话执行 | Chat runs | 只指从对话发生的非事项执行，不是新事项或新消息类型 |

`Issue`、`Execution` 仅保留在内部协议、原始诊断或历史实现事实中；普通界面统一使用 Task／Run。

### 状态显示词与映射

事项状态词、Run 状态、要求核对状态与补充递交状态是不同事实，不能互相倒写。联系人运行状态另行显示。下表的“事项显示词”只是 UI 词汇与优先级设计，基于现有 `Status`／`Archived`、Run 和问题事实做显示映射；不是新增的持久管理状态或新 enum。

| 类别 | 中文 | English |
| --- | --- | --- |
| 事项显示词（UI 投影） | 需处理／等你回答／进行中／未开始／已完成／已取消／已归档 | Needs attention／Waiting for you／In progress／Not started／Done／Canceled／Archived |
| Run | 等待开始／运行中／已结束／失败／已中断／结果未知／已停止 | Waiting to start／Running／Finished／Failed／Interrupted／Result unknown／Stopped |
| 要求核对 | 未核实／已满足／未满足 | Unverified／Met／Not met |
| 补充递交 | 已收到／待递交／已递交／待核对 | Received／Waiting to send／Sent／Needs check |
| 联系人运行 | 就绪／工作中／未连接 | Ready／Working／Not connected |

- 以上事项显示词是 UI 词汇与优先级设计，基于现有 `Status`／`Archived`、Run 与问题事实做显示映射；不新增、删除或改动持久状态，不要求数据迁移。`desktop/issues.go:14,156` 的 `Status` 已含 `waiting_user`／`needs_attention`，`desktop/issue_lifecycle.go:201` 会持久化 `waiting_user`；`desktop/store.go:82` 的 `Archived` 是独立 bool，不是 status enum。
- Run、要求核对和补充递交仍分开；不把旧失败 Run 反写成事项失败，也不把 Run completed 当成事项 Done。没有活动、没有活动 Run、没有聊天消息或没有新事件都不等于 Done；已完成、已取消、已归档等终态不因旧失败 Run 被覆盖。联系人聚合只统计相关且可见的未归档事项，优先级为需处理 → 等你回答 → 进行中 → 未开始；无活动不标 Done。
- 本表不是实现枚举：`Run` 等其余 enum／字段未全部逐项核过，继续按设计边界保留；实现必须按真实状态映射，不猜 Runtime 成功或新造持久状态。

### 完整句与文案

- 文案使用完整句模板，不拼接片段；数量与复数走 ICU／CLDR 规则。中文用“你”和 macOS 标准术语（访达、设置、复制、退出），保持平实；英文用美式英语和 sentence case，动词开头，避免名词堆叠。作用域（对话／事项／联系人）和状态必须与实际对象一致。
- 英文通常比中文宽；按钮不写死宽度，长文案换行、省略并保留完整 tooltip，关键操作不得被挤进溢出菜单。伪语言 `en-XA` 和长中文只作后续实现验证，不在本规范中声称已通过。
- 当前是设计约束，不是双语已接入的证据；实现由 #281 负责，界面截图、原生菜单、真实中文输入和用户试用仍需分别验收。

## 字体与层级

逻辑像素固定四档；全局缩放按比例，不增加第五档。权重、留白和位置负责其余层级。

| 层级 | 字号 / 字重 | 用途 |
| --- | --- | --- |
| 对象名／主要页或详情标题 | 16 / 500，极少 600 | 联系人、设置页、主区页面和详情页；禁止 20px 大标题 |
| 正文／输入／阅读、局部分组 | 14 / 400，分组 500 | 消息、编辑、设置内容、局部章节和分组标题 |
| 控件与列表 | 13 / 400，选中／必要动作 500 | 按钮、菜单、列表行、表单标签和联系人名称 |
| 必要辅助信息 | 12 / 400 | 日期、来源、快捷键、状态摘要；不再缩小或降对比 |

- 最小字号 12，最多四档；设置、详情、composer、Markdown 呈现共用同一组语义，不各自新增字号。等宽字体只用于代码等确有意义的原文，不用于标题、菜单、说明或数字装饰。
- 字体使用系统清晰无衬线及中文回退；不使用 Instrument Serif、Space Grotesk、Bricolage Grotesque。真实模型／协议名称保持正确拼写。
- 不用装饰标签、眉标、章节序号、装饰性代码面包屑、全大写小标题、`letter-spacing` 模拟小眉标、斜体、Emoji 或中圆点分隔界面文字；同一行需要并列身份／状态时，必须用不同语义字重、颜色和至少 12 逻辑单位间距明确分组，否则换行；不得把“Ready”和“Assistant”拼成一个标签，也不得修改用户原文。必要表单标签、真实状态和文件路径保留，界面状态用自然句子表达。
- 标题只用字号、字重和留白分层；正文与辅助文字保持可读，不用缩小文字掩盖溢出。设置页与右侧详情沿用同一语义层级，避免每行都像标题。
- 装饰 hairline 优先 0.5 逻辑 px；必要的输入边界、焦点与禁用语义保留并统一，不把装饰线当输入证明。嵌套容器的圆角按对应内外间距收敛，不随机混用。
- 本轮不改变色彩角色、导航层级、内容结构、事件权限或用户原文；不新增第五档字号、全局缩放或第三套布局。历史 8c 实现证据不改写，只作为已观察行为事实。

### 紧凑密度与尺寸

沿用现有布局角色，常用间距为 4／8／12／16：控件内部 4–8，相关项 8，独立组 12，页面内容内边距 16；Settings 字段组内 4、组间 12／16，主分组 24，表单内容最大 600 且左对齐。正文行高 1.5，Markdown 呈现同用 1.5（当前实现助手 Markdown 为 1.6，属待 [#278](https://github.com/HeimaoLST/Saki/issues/278) 修正的实现差异，不另立规范例外）；消息上下 8／左右 12，消息间 12，段落间 8；单行列表目标 32，双行联系人目标 44。图形 16，工具与 Send/Stop 命中区保持 32；单行页头目标 48，双行联系人名／状态约 56，不能为了数值隐藏状态或重叠。composer 默认总高目标约 90–100（两行正文、32 工具行、边界与常态内边距合计），多行、资料展开和错误按内容自然增长，整容器高度必须计入全部常态子元素；常驻 Enter/Shift+Enter 说明移到 Send 的已有 title/aria-description，不新增帮助行或组件。模型作用域和主动作始终可用。Settings 使用 32 控件和紧凑标签／分组，长错误和说明自然扩展，不把每一行都做成大卡片。

优先在主路径落实：首用／联系人、消息与 composer、事项／执行详情、阅读和 Settings；已有行为回归继续有效，不因外观密度改变而废弃。密度是首轮试样，实际字号/缩放可再按用户反馈校准；不在 HTML 原型中冒称 Qoder 实测。

使用规则：

- 中性背景承载正文；实心 `accent` 只用于 Send/Stop 主操作；选中控件和导航用 `selected`/`selected_text`（必要时叠加焦点环），焦点与错误／警告语义色保留，不因收束视觉重量而删除。工作区某状态下的唯一实心主操作（如 Answer／Continue／Read result）可使用现有中性角色，但仍须可发现、可聚焦。`success`、`warning`、`error` 同时配文字或图形，不用绿色猜完成。
- `line` 只作装饰分组，不能单独证明输入、焦点或选中；控件需要边界时用 `control_border`。当前 CSS 只把 `control_border` 用于搜索框、字段和 composer 等输入边界，装饰线继续用 `line`。
- 复制和普通工具使用不透明 `muted`；hover 只加底面，不以 opacity/filter 降低对比。仅 Send/Stop 主操作使用 `accent` 的默认/hover/pressed；选中控件／导航使用 `selected`/`selected_text`，不拿 brightness 代替核定值。
- 原生禁用沿用 MyGo 官方 Disabled 语义和默认绘制，不为候选禁用色单独加框架 patch；#221 的 `disabled_text`/`disabled_bg` 4.60/5.40 只是不透明候选，不是当前 native 门槛，实际默认变淡约浅 2.94/深 4.33 只作适配记录，不能写成当前渲染已达候选值。
- 必要的禁用原因、当前有效模型、错误和容量原因必须另用独立、可读的正常文字（普通文字仍以 4.5 为目标），不能只放在不可聚焦的 disabled tooltip；关键状态也不能只靠变淡区分。
- #221 的 92 对检查中 88 对有阈值通过、4 对仅记录；覆盖范围限于已列出的背景/状态组合，不宣称任意透明度、组件默认状态或原生渲染都通过。最终原生颜色、焦点、hover/pressed 仍待 GUI 主责验证；disabled 按官方默认绘制，不另加 patch。
- Adobe 实测参数：单色规则、基础色 `#365E4D`，原始输出为 `#365E4D`、`#709183`、`#A3C4B6`、`#9CF7D1`、`#6EFFC2`；这些原始值不直接铺满 UI。完整研究见 [#221](https://github.com/HeimaoLST/Saki/issues/221#issuecomment-6524653785)。


## 消息与复制

- 用户在右、Agent 在左；长回复不被拆成多条。中文段落、列表、表格、代码和来源保持可读。
- 不保留气泡内部独占一行的“复制”文字按钮。助手消息复制入口常驻；用户消息在 hover／focus 时显示，并保留可用的右键复制入口。两者都使用标准图标贴气泡外缘、与消息首行对齐，不参与气泡宽高计算，命中区至少 32×32，图形约 16；主导航（工作、历史、资料）始终静止可见，不依赖 hover。
- 助手复制入口常驻低权重；用户入口在 hover／键盘 `focus-within` 时显示，hover 不是唯一入口。显示时只增强底面，不改变文字色或对比度，也不以 `opacity:0` 隐藏；图标不能盖住正文、链接或代码，窄布局不产生水平滚动。
- 复制必须使用原有精确全文／代码复制逻辑，成功或失败用非布局位移的公告／短反馈表达；反馈不能推开消息或增加气泡高度；键盘入口与失败恢复回归保留，行为验收由 GUI 实施。
- 工具执行与消息分开：工具结果按 call 归属进入工作／详情，不因完成追加聊天回复。

## 统一 composer

一个完整容器：文字编辑区在上，工具栏在下，提示和错误也在容器内。

- 左侧资料／添加入口显示真实已有数量，展开后是 composer 内嵌的资料区；不得借原型增加不存在的资料能力。
- 右侧显示当前对话的实际模型短名和`对话`作用域；保持无 chevron。三选一优先用现有官方 Segmented；其他值选择器用明确前缀或现有图标标出选择行为，并显示当前值，保留可访问角色／状态；静止态、键盘 focus 和 tooltip 均可辨，并与可编辑输入框区分。HTML 原型保留原生 select 并用 CSS `appearance:none` 去掉平台指示，不新增自造菜单，保留原生键盘语义；该配置仅指 HTML 原型，不表示原生 GUI 直接沿用 CSS。原生 GUI 按 MyGo 官方组件配置达到同一无箭头效果；若 A2 实测仍不可辨，携实际样例交 PM 评估 A1 例外，不默认恢复 chevron 或自造控件框架。展开后可查看完整有效模型值，默认选项不能冒充已生效。模型仍使用现有有效模型／保存／应用／会话快照契约，不在原型中暗中修改活动 session。
- 发送/停止是本区域唯一实心 accent 主操作；发送使用发送上箭头图标，只在当前对话运行时，同一位置显示带明确“停止对话”文字的停止控件；不得误停事项工作或另一联系人。工作区页面的唯一主操作使用现有中性角色，不把 Send/Stop 的实心 accent 复制到其它动作。
- `Enter` 发送、`Shift+Enter` 换行；composition 中 Enter 不发送。真实系统 IME 仍按 #114 验收，HTML 键盘样本不替代原生。
- `Enter/Shift+Enter` 提示只使用 Send 已有的 title／aria-description，不新增常驻独占帮助行；正常态不重复“当前对话/模型/容量/停止范围”的实现说明。真实错误、容量、未知结果和保存错误在有实际阻塞时仍在 composer 内持续可读，各自给具体原因与恢复入口，不随快捷键提示隐藏或在输入聚焦时才出现。
- 不把资料、模型和会话信息重新拆成容器外的大按钮或 `Session` 行；不添加语音、审批或尚未实现的入口。

## 布局与右侧详情

- 默认只显示联系人栏和对话，右侧详情收起；中间内容最宽。默认联系人栏 200px（180–280），右区 340px（280–440），中间至少 480px；分隔线各 1px。联系人栏标题行保留 Contacts 与右侧 Add contact `+`；Hide 用同套图标；底部 Settings 是 32 高、左对齐的安静图标+文字行；搜索与 Active/Archived/All 当前值保持可见，不重复 Contact scope 标题。
- 布局断点按逻辑内容宽度（DIP）判断，不从 Retina 截图物理像素反推：
  - **宽 ≥1180**：打开详情时为联系人／对话／详情三域；详情仍默认收起，展开后沿用上述可调宽度偏好。
  - **900 ≤ 宽 < 1180**：打开详情时，联系人栏自动收为约 56 逻辑宽的头像条，对话至少 480，详情至少 300；960×640 下对话与详情必须同时可见、可编辑，composer 至少 440。
  - **宽 <900**：详情沿应用内整页返回模式，保留返回目标和原上下文；不增加遮罩或模态。
- 页头左侧是头像、联系人和状态；右侧工作、历史、联系人资料为统一图标工具组。三者打开同一右侧详情区的不同内容，一次只显示一个；当前项有选中态，再点关闭。详情收起时，页头工作入口必须显示相关事项计数或需处理提示；可打开对应事项，但不自动展开详情或生成聊天回复。
- 详情开关只由用户显式操作改变；用户打开详情后，布局几何按当前宽度断点决定（≥1180 为三域，900–1180 自动收为头像条，<900 为整页），这次自动收窄是响应式几何，不是自动打开详情。收消息、事项执行、联系人切换都不自动展开；切换详情保存各自的滚动位置和原入口焦点，不丢草稿。
- 窄窗口不压缩正文，也不使用遮罩弹窗；宽 <900 的详情改为应用内可返回页面，保留返回目标和原上下文。窄详情覆盖全应用时，被覆盖的联系人栏、主对话和分隔条必须从键盘顺序移除（`inert`／等效局部可见性），关闭、宽窗切换或页面返回后再解锁；不得把包含可见详情的祖先设为 inert。焦点目标只选择当前可见的宽窗 X 或窄窗左上返回。主区长阅读同样使用主区页面，不叠第二层浮层。
- 中间消息与右侧详情各自滚动。关闭详情、页面或阅读后恢复原入口、筛选、消息阅读位置和草稿。
- 900–1180 的自动压缩只在详情开启期间生效，不覆盖用户已有的联系人宽度偏好；关闭详情后恢复原联系人宽度、草稿、焦点和滚动位置。头像条中每项都能键盘到达，并有名称／tooltip 与语义状态。
- 边界验证至少覆盖 899／900／901 与 1179／1180／1181；浅色、深色、长中文、英文及伪语言下都不得遮挡、缩字或横向溢出。
- 工作／历史／资料／模型／上下文／结果阅读的映射：

| 路径 | 承载 |
| --- | --- |
| 工作概览、事项详情、执行记录 | 右侧详情区；详情内部可用短展开行 |
| 历史搜索与结果列表 | 右侧详情区；选择记录定位主体消息或打开主区阅读页 |
| 联系人资料摘要 | 右侧详情区；编辑复用完整 Settings 的联系人分类 |
| 模型选择 | composer 内短下拉，使用既有有效模型契约 |
| 对话资料 | composer 内嵌展开区 |
| 结果、文件、长历史 | 主区可返回页面 |
| 看板、日程、新建事项 | 主区页面；不再以自绘模态承载 |
| 设置 | 完整应用页面，保持独立分类与返回工作台 |

## 设置、资料与工作详情

- 全局 Settings 仍是完整页面：通用（外观、语言）、连接与模型、联系人资料、高级。联系人资料页头快捷入口打开同一设置页面的对应分类；不建立第二套表单、存储或配置来源。设置页返回 Back 在宽窄窗口使用同一左对齐、内容宽的箭头+Back 文字控件；32 高、默认透明，hover/pressed 与 focus 可辨，保留原 AX 名称、返回焦点、草稿与分类恢复。
- Paper/Night 是现有持久化主题标识；当前原型采用 #221 语义适配值，不另建主题对象或配置文件。
- 右侧联系人资料只给上下文摘要和“编辑完整资料”入口；名称／职责／工作要求的完整字段在 Settings 中修改，保存语义沿用现有未来默认值和会话快照。
- 工作区保持现有事项概览／详情、要求与依据、停止／继续、归档／恢复和成果阅读能力。事项详情中的补充要求可带回 composer，但必须保留已有定向派发和补充账本，不用聊天前缀模拟。
- 工作区顶部切换固定为“事项 / Tasks”和“对话执行 / Chat runs”；后者只指非事项的对话执行，不是新事项、消息类型或第二套执行入口。
- 历史在当前联系人的已加载对话内搜索；结果可回到主体消息。没有结果、未加载或读取失败要说明范围，不伪报空历史。
- 结果文件行本身就是阅读入口；打开主区阅读页，保留复制、打开、定位和失败反馈。系统文件选择器、原生打开／Finder 不属于 HTML 自绘改造范围。

## 控件、反馈与动效

- 普通操作至少 32×32 或 32 高；图形 16–18；Send/Stop 固定保留在模型旁，低频率工具可进入标准 Toolbar，关键动作不得被溢出菜单收走。静止态不默认套粗描边，但主要动作、列表行、下拉和状态必须可辨。
- 图标按钮有可访问名称和 tooltip；选中态、焦点、按压和禁用态分别可辨。复制图标只负责复制，不承担导航或菜单。
- 短下拉、tooltip、就地展开和短确认可用；普通工作流不使用大 Dialog 承载工作、历史、资料、模型、上下文或阅读。
- 下拉／菜单触发按钮保持无 chevron；三选一优先现有 Segmented，其他值选择器用明确前缀／图标、当前值和可访问角色体现选择行为，静止态、键盘 focus 与 tooltip 均可辨，并与可编辑输入框区分。HTML 原型以原生 select + CSS `appearance:none` 去掉平台指示，不新增自造菜单；原生 GUI 按 MyGo 官方组件配置达到同一效果，不直接沿用 CSS。若 A2 实测不可辨，携实际样例交 PM 评估 A1 例外，不默认恢复 chevron 或另造控件；导航返回、发送和真实层级展开图标不混同为下拉装饰。
- 不使用紫色渐变、多层阴影、装饰性半透明叠层、彩色卡片左竖线或层层带框容器；以布局、留白和必要 hairline 分组。必要的输入边界、焦点和禁用语义不删。
- 必要确认就地表达，不为去弹窗默默执行取消、丢弃或不可逆操作。
- 不使用装饰性滚动动效、视差、逐项入场或生硬过渡；必要状态过渡使用短时长，`prefers-reduced-motion` 时取消位移动画。助手复制图标常驻，用户入口在 hover／focus 与右键可用，键盘焦点始终可到达。
- 状态变化用一条简短公告，不重复播报整段正文；错误、容量与 unknown 保留事实和下一步，不伪装成功。

## 原型状态与边界

- HTML 可实际切换：三项详情、事项列表／详情、历史搜索、联系人资料摘要、设置分类与返回、composer 资料展开、模型短下拉、发送／停止模拟、结果／看板／日程页面。
- 原型不连接 Runtime，不持久化联系人、草稿、模型或事项；发送和停止只是页面状态。所有示例内容标注为设计样本。
- 原型不证明原生 MyGo 渲染、真实模型、系统 IME、剪贴板、文件系统、权限、断连或退出恢复。核定版本 API 与真实窗口行为由 GUI 主责在对应实现中验证。
- 旧 v08 的模态工作抽屉、阅读浮层、容器外模型按钮和复制大文字行不再作为有效标准；历史保留在 Git，不并列维护两套规则。
- HTML v10 的旧断点和布局尚未同步本规范，只作历史设计参考，不能反向覆盖本规范；现行规范优先，后续原型同步在 #216 追踪，本次不改 HTML。
- 普通流程不使用模态遮罩是用户要求，不把它写成通用设计理论禁止所有系统级确认。

## 开发交接与验收

PM 负责本规范、原型和文案；GUI 主责按核定版本的 MyGo 实现，Runtime／协议事实仍以对应模块文档为准。先复用现有 Button／Toolbar／Text／布局和主题角色，再处理视觉精修；不为本规范新建通用路由、弹层框架或第二套 store。

| 验收 | 可观察结果 |
| --- | --- |
| 复制 | 助手入口常驻、用户入口 hover/focus 与右键可用；均贴气泡外缘首行、不计气泡宽高；精确复制全文；不遮挡、无横向滚动 |

| 详情 | 工作／历史／资料同一右侧详情区，一次一个，当前有选中，再点关闭；默认收起，收起时页头工作入口保留相关计数／注意提示 |
| 返回 | 详情、设置、历史和结果页面返回原入口、草稿、筛选和滚动位置 |
| 设置与资料 | 资料编辑进入完整 Settings 联系人分类；不出现第二套表单或存储 |
| 非模态 | 常规流程无大 Dialog；窄窗详情为应用内页面，左上图标＋文字返回；宽窗侧栏可 X 关闭；Escape 只退一层 |

| 配色 | 语义角色按 #221 表映射；复制/工具用不透明 muted；accent 状态、control_border、line、warning/error 不只靠颜色；92 对边界外不宣称通过 |
