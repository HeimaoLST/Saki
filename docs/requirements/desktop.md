## 产品目标与范围

GUI 是以联系人为入口、帮助用户持续完成工作的个人 Agent 工作台。第一批用户是维护者及朋友。目标流程是：**启动与配置 → 选择联系人和工作目录 → 提交任务及资料 → 查看执行并可停止 → 使用结果 → 重启后继续**。

首轮沿用当前联系人和单会话映射。代码阅读、文档整理是建议的试用任务，不是已经确认的用户选择；具体任务由实际试用记录确定。新增增强挂后续迭代，不自动扩大 [MVP](mvp.md) 的完成条件。macOS arm64 是首个实际验收环境，其他平台支持需单独证据。

| 层 | 负责 | 不承担 |
| --- | --- | --- |
| GUI 应用层 | 联系人、草稿、工作目录选择、设置、主题、资料选择、结果展示、未读和窗口生命周期的产品策略 | 模型／工具执行循环、猜测执行成功、第二套权威历史 |
| Agent Runtime | 会话与任务、实际生效配置、模型与工具调用、取消、并发、执行历史、上下文预算 | 联系人、窗口、主题、业务工作流 |
| 宿主配置 | 提供模型连接与凭据，按 Runtime 契约注入 | 在 GUI 复制协议适配器或模型校验规则 |

统一使用现有 Go/MyGo 应用和 stdio 接口。读取历史走 Runtime API；资料索引、收藏等未来产品能力不因此获得实施范围。GUI 的新字段必须对应已交付的契约；本文不规定尚未定稿的 API 字段或构造假的能力探测接口。

## 验收方法

后文每个验收 ID 都要填写 `PASS / FAIL / 未验 / N/A（理由）`，附候选 GUI SHA、Runtime SHA、环境、复现步骤和证据路径或链接。旧版本证据只能说明旧版本；包内 GUI 与 Runtime 可能来自不同提交，分别记录。

| 证据 | 适用与要求 |
| --- | --- |
| 行为回归 | 复用既有 Go 测试；只为真实缺陷、失败路径或非平凡不变量补测试。模型、文件读写或并发用本地受控 provider／临时目录／协调信号，不靠 sleep |
| 真实进程接线 | 涉及发送、配置、资料、恢复或并发时，Go 客户端连接实际构建的 Rust 进程；mock DTO 成功不等于接入通过。既有五项集成测试仍须实际 PASS，未设置 binary 导致 skip 不算 |
| 视觉与交互 | 视觉变化比较同场景浅色／深色、默认窗口、960×640、展开设置和宽窗口。原生操作单独记录；主题、中文组合输入、窗口按钮不能只用 headless 截图证明 |
| 真实用户试用 | 用户独立完成选定任务，记录产出、需要他人救场的步骤、恢复继续情况和反馈；开发者演示不替代用户试用 |

实现者负责模块测试，GUI 主 agent 负责评审和适用原生运行验收，QA 负责 CI 工程。无需另建 QA 人工审批队列。复用既有测试入口与 required CI，避免每个小改动重复整套人工验收；按本次影响选取相关 ID，未覆盖不得标 PASS。

## G1 启动诊断与可复现使用

用户价值：从 Finder 打开应用后，用户能辨认阻碍并按说明完成首次使用。范围：现有启动、错误展示和本机构建／配置说明；不引入另一套凭据存储或自动安装服务。

| ID | 场景与通过条件 |
| --- | --- |
| G1-1 | 用独立临时用户配置目录从 Finder 打开包含 Runtime helper 的 `.app`，不依赖开发者 shell cwd/env。缺配置时显示可操作说明，包括现有支持的配置位置／变量名及重新启动步骤；按该路径配置后可完成一次受控任务。不得笼统承诺无需配置 |
| G1-2 | 分别覆盖 helper 缺失、启动失败、可识别的配置缺失、provider 返回认证失败。用户看到实际阶段、原因及可采取的操作，草稿保留；未知错误保留有界诊断而不猜原因。Runtime ready 只能表示连接就绪，不能显示“模型已验证可用” |
| G1-3 | 可查看当前联系人工作目录和已有接口确认的信息。尚未获得的模型／连接信息显示未知或待加载；实际生效模型的完整展示与选择交给 G6，不把环境变量猜测显示成 session 事实 |
| G1-4 | 打开配置说明、查看状态或启动应用不自动发推理请求。诊断与截图不得包含凭据。配置修正后的重启恢复已有联系人、草稿和历史；不创建替代 store 掩盖读取失败 |

依赖：现有接口可实施。首轮可使用已有文件配置并提供准确指引；图形化连接选择／配置消费见 G7。证据：冷启动原生记录、故障注入、受控 provider 的调用记录。

## G3 结果阅读与复制

范围：现有消息与工具结果展示。先交付标题、段落、列表、引用、链接、行内代码和 fenced code；复用当前 MyGo 能力，依赖升级需要具体理由。语法高亮、表格与完整文件预览可后续按需提出。

| ID | 场景与通过条件 |
| --- | --- |
| G3-1 | 同一正文在流式增长、最终结果与恢复历史中保持内容一致；未闭合代码块可继续显示，后续增量不丢字或重复。空、中文、多段长文本可读 |
| G3-2 | 可复制完整消息原文和单个代码块；代码复制保留缩进／换行、不含 fence。用户选择文字或上翻时，新增输出不反复抢焦点或滚回底部；主动回到最新位置后恢复跟随 |
| G3-3 | 长代码换行、不撑破窗口，默认阅读不要求横向移动；链接仅在用户操作时交给系统打开；复制失败有反馈。纸白/夜林下都可读；若对应主题尚未集成，阶段证据明确其实际方案，不冒称目标已完成 |
| G3-4 | 工具摘要、Details 和错误原因在独立工作区保留，不为工具事件新增聊天气泡。截断必须可辨识，复制范围写清楚：完整 GUI 已收到的结果或明确标注的截断片段，不把最多 2000 字的预览称为完整输出 |

依赖：现有文本／历史协议，无新 Runtime 前置。工具权威 diff 属于 #33 契约后的独立范围，GUI 不从模型描述推测磁盘实际改动。证据：流式／恢复内容对照、原生剪贴板读回、长代码和工具失败截图。

这是现有交互的具体回归验收和发现问题后的局部修复，不是重新设计输入系统，也不要求为了覆盖率机械添加测试。

| ID | 场景与通过条件 |

## G5 执行反馈、停止与恢复共同约束

以下是所有任务必须保护的现有行为，不另建“重做任务系统”的功能单。受某个改动影响时验收对应 ID。

| ID | 场景与通过条件 |
| --- | --- |
| G5-1 | 已接受／开始／执行中／成功／失败／中断按 Runtime 事实显示；工具错误不直接等于整个任务失败。状态不能只靠颜色，失败原因可读 |
| G5-2 | 切换联系人和查看历史不停止任务。Stop 精确针对用户选中的任务；取消等待、成功、迟到取消不串到下一任务 |
| G5-3 | 断连、丢失发送响应等不能确认结果时显示未知，保留用户输入与可核对信息，不自动重发。按现有重启／加载／历史读取路径核对，恢复与查看不触发推理或重跑工具 |
| G5-4 | 关闭窗口／Cmd+Q 复用现有 drain 与退出策略；等待期间有反馈、不假称已退出。重启可恢复已落盘历史与草稿，不承诺关窗后后台继续执行 |

恢复后状态仍按 Runtime 事实判定，不能为了视觉完整度把未知改成成功。改变重连、重试、后台执行或队列策略需要独立需求，不能藏在本轮“体验优化”里。

## G6 当前模型与空闲切换

范围：同一连接内的模型选择入口与实际配置展示，依赖 Runtime #105（及其 #104 基础）。跨连接／prompt 修改属于 G7。

| ID | 场景与通过条件 |
| --- | --- |
| G6-1 | 读取并展示 Runtime 返回的有效模型／配置；可选模型来源复用 Runtime，目录不可用按实际契约处理，GUI 不维护第二份模型能力表 |
| G6-2 | 空闲时 A→B→A，只有更新成功才替换有效模型显示；下一任务、恢复后的显示与真实请求一致。取消设置不提交修改，过去消息和执行事实保持 |
| G6-3 | 已接纳或正在执行时不可改活动任务配置。即使显示空闲但请求与发送竞态，仍正确处理 Runtime busy／revision conflict；失败、非法配置或不支持的 continuation 保留原有效值并解释原因 |
| G6-4 | 切换成功但响应丢失时先重读有效配置再显示结果，不盲目重试；不通过重建联系人、丢历史或直接写 Rust 存储规避失败 |

解除依赖：#105 接口、目录来源、错误语义与实际 Runtime 交付可供消费。证据：Go→实际 Rust→受控 provider 请求模型，覆盖切换／busy／冲突／恢复；仅下拉框截图不算。

## G8 随任务提交文字资料

范围：composer 中添加、预览、移除命名文字资料；首轮覆盖粘贴片段与显式选择的 UTF-8 文本文件。依赖 Runtime #108。不建设附件框架、目录扫描、PDF/OCR、向量库或自动同步文件。

| ID | 场景与通过条件 |
| --- | --- |
| G8-1 | 发送前看见本次资料名称与内容；可编辑／移除，不发送已移除资料。无法读取、非文本或超过已声明限制时给出具体反馈，不静默截断 |
| G8-2 | 文件导入时形成用户可预览的文本快照；文件之后变化不悄悄改变已展示／发送内容。再次读取必须由明确用户操作触发 |
| G8-3 | 正文和资料通过统一 task 输入提交一次，保留名称与来源边界；不拼成 system 指令，也不在正文和 context 中重复注入。被拒或本地保存失败时保留待发资料和草稿 |
| G8-4 | 接纳后资料归属该任务；不默认附到后续每次发送。历史／压缩／恢复按 Runtime 契约保存可解释来源，UI 不宣称“仅本轮使用后自动删除” |
| G8-5 | 待发资料随各联系人草稿隔离并可重启恢复；恢复后仍是保存的快照。明确接纳后清空本次待发项；结果未知时保留并禁止自动重发 |

解除依赖：#108 输入限制、历史投影与错误语义已交付；GUI 的草稿保存扩展保持旧 store 可读。证据：源文件变化、移除、拒绝、重启与 Go→实际 Runtime 的单次输入核对。

## G9 多联系人并发与完成提示

范围：依赖 Runtime #61，让已有联系人能同时执行；每个联系人沿用当前绑定会话。首轮完成提示是应用内状态／未读，不默认增加系统通知权限或后台常驻服务。

| ID | 场景与通过条件 |
| --- | --- |

## 开发领取与交付

1. 从 #111 的任务表选择自己业务线的 ready 单；blocked 只做不依赖接口的设计核对，依赖交付后确认实际契约才转 ready。标题栏、主题、阅读都可能改 `view.go`，由 GUI 主责串行安排，不能因 issue 不同就并写。

3. PR 写明对应 G 编号及适用共同约束，更新 `docs/design/desktop.md` 的实际行为；不把本文的需求改成已经通过的证据清单。
4. `go test ./...`、适用真实进程／原生验收与 required CI 均记录真实 SHA。完成 commit／push／PR 后仍要按有效授权推进目标分支集成与收尾；未集成保持 review，不能因截图或 CI 绿提前关闭。
5. PM／用户另外执行实际任务试用：首次配置 → 提交 → 获取可用结果 → 重启继续，记录完成情况和需要救场处。功能验收、真实试用、稳定发布分别判断。
