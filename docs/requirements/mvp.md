# 两端 MVP 需求：TUI + GUI 验证同一 Runtime

更新日期：2026-10-20。
状态：**需求与验收边界**（产品目标已确认；平台细节、代表任务、试用人数与周期待定）。
事实基线：`dev@8bffd85`。实时任务、依赖与完成状态以 [#50](https://github.com/HeimaoLST/Saki/issues/50) 及各执行 issue 为准；本文不维护任务表或完成计数。

## 用户价值与范围

第一用户是作者本人，其次是朋友：先让自己和朋友在日常任务中觉得好用，再用真实使用逐步打磨 Runtime。TUI 与 GUI 是两个宿主，验证的是同一套 Runtime 核心——同一模型／工具／会话／上下文／事件语义，而不是两套行为。

首轮 MVP 的价值是“真的能用来做事”，不是界面演示、截图、mock 或 CI 绿灯。演示数据、headless 渲染与自动检查都不能冒充真实模型执行或用户试用。

## 已确认的用户目标

1. **真实执行**：在 TUI 与 GUI 中都能完成真实模型 → 工具 → 结果的任务，活动、输出、失败与归属来自 Runtime 真实事件。
2. **持久历史**：跨进程保存并恢复会话；重启后能继续工作；仅查看／加载历史不重跑模型或工具。
3. **可信执行事实**：流式正文、工具活动、失败、取消与任务归属可被用户看见，且不会串到其他会话。
4. **可直接使用的默认助手**：首次使用无需先定义 profile；默认通用助手即可提交任务，宿主所需的模型／凭据／工具配置确实可运行。个性化设置为可选；首轮不要求完整 profile 编辑，尚未接线的设置不得显示为已生效。已支持的配置更新只影响未来请求，不改写历史。
5. **可复现启动**：按文档化的本地配置即可启动并提交任务；不支持“只有作者本机偶然能跑”的状态。
6. **首轮交互边界**：允许同一宿主只有一个活动任务，但必须明确显示 busy；查看 B 或切换历史不能取消、替换 A。并发执行不是首轮硬门槛。
7. **平台边界**：首个工程验证目标是 macOS arm64（依据现有 QA 环境与已发生的真实运行／PTY 证据）；其他系统没有真实运行证据前不宣称支持。
8. **证据区分**：原生窗口、键盘焦点与输入法需要真实窗口证据；headless／预览测试只能证明布局与确定性渲染，不能替代。

## 非本阶段硬门槛

以下事项按主要任务的实际需要再决定优先级，不因为写在 backlog 或“以后可能有用”就自动成为 MVP 硬门槛：

- 多 session 并发（#61）与历史检索（#62）；首轮只有单活动任务也可接受。
- #31／#32／#33 等 runtime 契约增强、其他 p2 TUI 候选。
- 成长机制、SDK／更多宿主、OAuth／多账号、视觉润色与大规模性能优化。

已确认的用户可见行为（例如查看 B 不取消 A、恢复不重跑）仍须验收；不被列为硬门槛的是实现范围，不是已承诺的语义。

## 结果与证据矩阵

三个阶段分开判断，不互相冒充：

| 阶段 | 结果 | 必需证据 | 不能证明 |
| --- | --- | --- | --- |
| 工程候选（进 `dev`） | 两端所需能力与回归已实现并集成 | required CI 真实通过；主 agent 代码评审；行为测试与适用运行记录；两端真实 provider 的模型／工具冒烟 | 用户觉得好用；广泛平台支持 |
| 首批真实试用 | 本人及朋友用选定的真实日常任务完成实际工作 | 真实模型／工具运行摘要；历史恢复与仅查看不重跑；失败／取消与归属记录；参与者反馈、阻碍与人工补救 | 稳定发布质量；广泛平台支持 |
| 稳定发布（`master`） | 发布范围、全套门禁与回归验收通过 | 发布 PR、全套检查与回归结论、目标版本、已知限制；发布 PR 合并授权 | tag／GitHub Release／部署已获授权 |

补充规则：

- **CI 绿 ≠ 用户觉得好用**：自动检查只证明机器门禁；实际可用性由主 agent、PM 与用户真实试用判断。
- **试用证据不可编造**：未发生的试用不写“已试用”；不虚构人数、周期或代表任务。
- **平台不越权宣称**：没有真实运行证据的系统只记为未验证。

## 角色与责任（QA 聚焦 CI）

- **实现者**（TUI／GUI／Runtime）：交付功能与有价值的回归测试；模块行为测试归实现模块。
- **QA**：维护 CI 工程与自动检查运行可靠性，反馈真实失败；不接产品人工验收或独立 `APPROVE` 队列，不直接改产线。
- **主 agent**：负责代码评审和适用实际运行／验收；可评审自己或子 agent 的产物，但须如实记录作者／评审者，不冒充独立评审或人类结论。
- **PM／用户**：负责真实试用与“是否好用”的判断；长期需求、索引与验收标准由 PM 维护。
- 非 breaking change 在主 agent 评审与 required CI 通过后按 [AGENTS.md](../../AGENTS.md) §0.2 预授权合并；`master` 保持生产稳定，发布需范围、全套验证与发布 PR；tag／Release／部署不随合并自动授权。

## 待定事项

- **代表任务**：已向用户询问，尚未答复。在此之前，工程验证可以建议代码阅读和受控小改动，但不得声称用户已选择任务或朋友已试用。
- **试用范围**：参与人数、试用周期与具体任务类别未冻结，不擅自填入数值。
- **平台**：macOS arm64 是首个工程验证目标，不代表用户已承诺唯一平台；其他系统待真实证据。
首轮取消、连接生命周期与 busy 行为按 [Runtime API](../design/runtime-api.md) 的既定契约实施；后续并发与同 session 追加策略按各自任务演进，不把已定的首轮契约重新当作待确认前置。
